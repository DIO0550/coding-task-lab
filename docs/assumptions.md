# 実装上の判断と根拠

## 点数計算

- `docs/spec-phase1.md` の役名一覧・点数早見表・符計算付録は TODO のため、標準的な4人リーチ麻雀の一般的な定義に基づいて実装する。
- 出力の役名は英語スネークケースとし、同一役が複数対象になる場合は `yakuhai` のように同名役を複数件返すのではなく、翻数を合算した1件として返す。
- 赤5(`0m/0p/0s`)は手牌内では通常の5として面子判定し、赤ドラ1枚として翻数に加算する。
- `dora` / `uraDora` は仕様どおりドラ表示牌ではなくドラそのものとして扱う。
- 裏ドラは `riichi` が `riichi` または `double` のときだけ加算する。
- 役満は複合あり、ダブル役満までを個別役の上限として扱う。複数役満の合計は複合として点数に反映する。
- 数え役満は13翻以上の通常役として扱い、役満役が成立している場合は通常役・ドラを点数に混ぜない。
- 平和ツモは仕様どおり20符、七対子は25符固定とする。平和ロンは30符として扱う。
- 複数の面子分解がある場合は、最終支払い総額が最大になる解釈を採用する。

## ゲーム進行・CPU

- CPU自動和了が「なし」の場合、初期実装ではCPUは自動和了を宣言せず打牌を継続する。仕様上「レベルに応じた判断で和了するかを選択してよい」とされているため、より細かな判断は将来のAI強化対象とする。
- 後付けなしは流派差が大きいため、初期実装では「副露手のロンで、和了牌によって初めて役牌刻子だけが成立するケース」を後付けとして禁止する。タンヤオ・染め手・混全帯么九など、待ち以前から手全体に成立している役は後付け扱いしない。
- 入門/標準/上級の差は、初期実装では打牌候補の評価重みで表現する。入門は孤立牌・字牌、標準はシャンテン改善、上級は標準に安全牌寄りの評価を加える。
- CPUリーチ判断は、入門はテンパイ時に常に宣言、標準は残り山または点数状況を見て宣言、上級は他家リーチ中の追っかけを控える初期実装とする。
- 鳴き判断は公開情報と自分の手牌だけで行い、山や他家手牌は参照しない。
- カン後の嶺上牌処理は局進行エンジンの状態として扱うが、初期 UI では可能アクション表示と自動進行に重点を置く。
