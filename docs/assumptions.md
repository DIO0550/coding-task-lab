# docs/assumptions.md — 仕様の解釈と判断基準

本プロジェクトにおける仕様の曖昧点に対する判断およびその根拠を以下に記録する。

## 1. 牌表現と赤ドラ (Part 1 / Part 2)
- 入力 `0m`, `0p`, `0s` はそれぞれ赤5萬・赤5筒・赤5索を表す。
- 役判定・面子分解・勝敗判定においては通常の `5m`, `5p`, `5s` として扱う。
- ドラ判定において `0m` は赤ドラとして 1 翻を加算する。さらにドラ表示牌による指定ドラが `5m` の場合は、通常のドラ 1 翻 + 赤ドラ 1 翻で合計 2 翻として加算する。

## 2. 符計算およびダブル風牌の扱い
- 連風牌(場風と自風が一致する字牌)の雀頭は 4 符とする(場風 2 符 + 自風 2 符)。
- 平和ツモは一律 20 符固定(ツモ 2 符は加算しない)。
- 七対子は一律 25 符固定(切り上げなし)。
- 食い平和形のロン(門前でない平和形での他家からの上がり)は基本符 20 符 + 門前加算 0 符 = 20 符を 10 符単位に切り上げて 30 符とする。

## 3. 役満の複合および数え役満
- 役満の複合を認めるが、最大でダブル役満(2倍役満)までとする。
  - 例: 大三元 + 字一色 = ダブル役満 (子 64,000点 / 親 96,000点ロン)
  - 例: 四暗刻単騎 / 大四喜 / 純正九蓮宝燈 / 国士無双十三面待ち = ダブル役満
- 役満役が成立している場合、通常の懸賞役(ドラ・裏ドラ・赤ドラ)や通常役は加算しない。
- 通常役の合計が 13 翻以上で役満役がない場合は「数え役満」(シングル役満)とする。

## 4. 高点法 (High Score Selection)
- 手牌が複数の面子分解・待ち解釈を持つ場合、役・翻・符・得点の計算を行い、最終的な獲得点数(total score)が最も高くなる解釈を採用する。

## 5. CPU の行動と自動和了
- 「CPU自動和了: あり」の場合、CPU は和了形かつ役が存在するときに必ずツモ/ロンを宣言する。
- CPU の思考アルゴリズムは卓の公開情報(自身の捨て牌・他家の捨て牌・ドラ表示牌・鳴き面子)および自身の持ち手牌のみを参照し、山札や他家の非公開手牌を参照しない。
- CPU レベル:
  - 入門: 孤立牌・字牌優先打牌、簡易鳴き、テンパイ時即リーチ。
  - 標準: 向聴数(シャンテン数)および有効牌受け入れ枚数の計算に基づく打牌。他家リーチに対する安牌(現物)打牌による降り。
  - 上級: 標準に加え、危険度評価(現物・筋・壁等)に基づく押し引きおよび打点効率選択。

## 6. 同点時の順位決定
- 終局時に持ち点が同点の場合、起家(東1局の親)から近い座順(東家 > 南家 > 西家 > 北家)を上位とする。
