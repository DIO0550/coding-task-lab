# docs/spec-phase1.md — 麻雀エンジン仕様(Phase 1)

4人麻雀(リーチ麻雀・標準ルール)の**点数計算エンジン**と、**実際にCPUと対戦できるゲーム進行・CPU対局エンジン**を実装する。
点数の計算結果を表示するだけでは Phase 1 の完了とは認めない。対戦画面から対戦を開始し、配牌からツモ・打牌・鳴き・和了・流局を経て終局までプレイできること。

## 関連仕様

- 対戦画面の画面仕様は [docs/spec-match-screen.md](./spec-match-screen.md) を参照。

## スコープ

| 含む | 含まない(将来フェーズ) |
|---|---|
| 和了判定(通常形・七対子・国士無双) | 三人麻雀 |
| 役判定(1〜13翻、役満) | ローカル役 |
| 符計算 | オンライン対戦・通信同期 |
| 点数計算(子/親、ツモ/ロン、本場・供託) | 牌譜保存・観戦機能 |
| 牌山生成・洗牌・配牌 | 途中流局(九種九牌・四風連打など) |
| ツモ→打牌のターン進行 | 高度な読み(山読み・鳴き読み)AI |
| 副露(チー・ポン・カン)と優先順位 | |
| リーチ宣言・供託・裏ドラ | |
| 和了処理・流局処理・連荘・輪荘 | |
| 東風戦/半荘戦の終了判定・順位決定 | |
| CPU 対局 AI(入門/標準/上級) | |

## 採用ルール(曖昧さ排除のための確定事項)

- 喰いタン: あり
- 後付け: あり
- 平和ツモ: 20符
- 七対子: 25符固定
- 切り上げ満貫: なし
- 役満の複合: あり(ダブル役満まで)
- 数え役満: 13翻以上
- 人和: 採用しない
- 緑一色に發: 不要(發なし緑一色も役満)

※ 上記以外で解釈が分かれる事項を発見した場合は、実装内の `docs/assumptions.md` に判断を記録すること。

# Part 1: 点数計算エンジン

## 入出力JSON契約

### 入力

```jsonc
{
  "hand": ["1m", "2m", "3m", "4p", "5p", "6p", "7s", "8s", "9s", "ton", "ton", "ton", "5m"], // 純手牌(和了牌含む)
  "melds": [ // 副露(なければ空配列)
    { "type": "chi" | "pon" | "kan" | "ankan", "tiles": ["1m", "2m", "3m"] }
  ],
  "winTile": "5m",
  "winType": "tsumo" | "ron",
  "seatWind": "ton" | "nan" | "sha" | "pei",
  "roundWind": "ton" | "nan",
  "dora": ["3m"],          // ドラ表示牌ではなくドラそのもの
  "uraDora": [],           // リーチ時のみ有効
  "riichi": "none" | "riichi" | "double",
  "ippatsu": false,
  "situational": []        // "haitei" | "houtei" | "rinshan" | "chankan" | "tenhou" | "chihou"
}
```

牌表記: `1m`〜`9m`(萬子), `1p`〜`9p`(筒子), `1s`〜`9s`(索子), `ton/nan/sha/pei/haku/hatsu/chun`(字牌), 赤5は `0m/0p/0s`

### 出力(和了時)

```jsonc
{
  "valid": true,
  "yaku": [ { "name": "pinfu", "han": 1 } ],   // 役名は英語スネークケース(別表参照)
  "han": 3,
  "fu": 30,
  "score": {
    "total": 5800,
    "payments": [ ... ] // ツモ時は支払い内訳
  }
}
```

### 出力(和了不成立 / 役なし)

```jsonc
{ "valid": false, "reason": "no_yaku" | "not_winning_hand" | "invalid_input" }
```

# Part 2: ゲーム進行・CPU対局エンジン

Part 1 の点数計算エンジンの上に、実際に4人麻雀を最初から最後までプレイできるゲーム進行エンジンと CPU 対局 AI を実装する。
対戦画面([docs/spec-match-screen.md](./spec-match-screen.md))は本エンジンを通じて「結果を表示するだけ」ではなく「実際に対戦する」体験を提供する。
和了判定・役判定・符計算・点数計算は Part 1 のエンジンを公開API経由で再利用し、**重複実装しないこと**。

## 牌山・配牌

- 牌は全136枚。赤ドラ「あり」設定時は 5m/5p/5s のうち各1枚を赤5(`0m/0p/0s`)に置き換える。
- 対局開始時に牌山をシャッフルし、王牌14枚を確保する。
- ドラ表示牌を1枚めくる。カン成立ごとに新ドラ表示牌を1枚追加する(最大5枚)。
- 各プレイヤーへ13枚を配牌する。親(起家)は東家から開始する。
- 残り山枚数は「牌山合計 − 王牌14枚 − 配牌 − ツモ済み枚数」で管理し、画面へ提供する。

## ターン進行

ゲーム進行は以下の状態機械として実装する。

1. 手番プレイヤーが山から1枚ツモる。
2. 手番プレイヤーは以下から行動を選択する。
   - ツモ和了(和了形かつ役ありの場合のみ)
   - カン(暗槓・加槓)
   - リーチ宣言(門前・テンパイ・持ち点1,000点以上・残り山4枚以上の場合のみ)
   - 打牌
3. 打牌に対し、他家は以下を宣言できる。優先順位は **ロン > ポン/カン > チー**。
   - ロン(和了形かつ役あり。フリテンでないこと)
   - ポン / 明カン
   - チー(下家のみ)
   - パス
4. 誰も宣言しなければ次の手番(下家)へ移る。
5. 和了または山が尽きるまで 1〜4 を繰り返す。

### リーチ

- リーチ宣言時に1,000点を供託へ出す。
- リーチ後は和了牌以外をツモ切りする(手替え不可)。
- リーチ者の和了時は裏ドラをめくり、Part 1 エンジンへ `uraDora` として渡す。
- 一発・ダブルリーチの成立条件を管理し、エンジン入力へ反映する。

### フリテン

- 自分の捨て牌に和了牌が含まれる場合、ロン和了できない(ツモ和了は可)。
- リーチ後の見逃しは以降ロン不可とする。

### 和了処理

- 和了宣言時は Part 1 の点数計算エンジン(公開API)を呼び出して役・翻・符・点数を計算する。
- 点数移動(ツモの支払い内訳・ロンの放銃者支払い・本場加算・供託回収)はエンジンの結果に従って適用する。
- 画面側で点数計算ロジックを重複実装しないこと。

### 流局

- 山が尽きたら荒牌流局とする。
- テンパイ/ノーテンを判定し、ノーテン罰符(場3,000点)を移動する。
- 親がテンパイなら連荘(本場+1)、ノーテンなら輪荘(本場+1)とする。
- 供託は次局へ持ち越す。

### 連荘・輪荘・終了判定

- 親の和了: 親継続、本場+1。
- 子の和了: 親を下家へ移し、本場を0に戻し、次局へ進む。
- 東風戦は東4局まで、半荘戦は南4局まで。
- いずれかのプレイヤーの持ち点が0点未満になったら終局(トビ)とする。
- 終局時に持ち点で順位を決定する(同点は起家に近い方を上位)。

## CPU 対局 AI

CPU の手番では、人間の入力なしに自動で行動を決定する。レベルごとの要件は以下とする。

| レベル | 打牌 | 鳴き | リーチ | 押し引き |
|---|---|---|---|---|
| 入門 | 孤立牌・字牌から切る単純な牌効率 | 役に関係する明確な鳴きのみ | テンパイしたら常に宣言 | 考慮しない |
| 標準 | シャンテン数と受け入れ枚数を考慮 | 役と打点を考慮 | 打点・待ちの良さを考慮 | 他家リーチ時に現物を優先 |
| 上級 | 標準に加え打点効率を考慮 | 標準と同様 | 標準と同様 | 危険牌評価と降り判断を行う |

- 「CPU自動和了: あり」の場合、CPU は和了可能(役あり)なら必ずツモ/ロンを宣言する。
- 「CPU自動和了: なし」の場合、CPU はレベルに応じた判断で和了するかを選択してよい(初期実装では「あり」と同じ挙動を許容し、判断を `docs/assumptions.md` に記録する)。
- CPU の思考は同期的な純粋関数として実装し、`(卓の公開情報 + 自分の手牌) → 行動` の形にする。乱数を使う場合はシードを注入可能にしてテスト可能性を保つ。

## アーキテクチャ要件

- ゲーム進行の状態遷移は `(state, action) → state` の純粋関数(reducer 形式)で実装し、UI・React から分離する。
- 牌山シャッフルなど乱数を伴う処理は乱数生成器を注入可能にし、テストで再現できるようにする。
- Part 1 の点数計算エンジンとは公開APIを通じてのみ連携する。
- 外部ランタイム依存は追加しない。

# 受け入れ基準

- `echo '<入力JSON>' | pnpm --silent calc` で出力JSONが返ること
- 対戦画面から対戦を開始すると、配牌・ツモ・打牌・鳴き・リーチ・和了・流局を経て局が進行し、東風戦/半荘戦を最後までプレイできること
- 人間1人 + CPU3人の構成で、CPU が自動で打牌・鳴き・和了すること
- 和了時の点数計算が Part 1 エンジン経由で行われ、点数移動が [docs/spec-match-screen.md](./spec-match-screen.md) の「点数反映」規則と一致すること
- `AGENTS.md` および `rules/` 配下の規約に準拠していること
- 本仕様の全項目(点数計算・ゲーム進行・CPU行動決定)に対するテストを自作し、すべて通ること
